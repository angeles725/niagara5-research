For each delta above, one line of rationale (WHY it matters, what it costs, expected impact):

- **#1** — a silent undercount from a quote-style gap looks like a clean, confident `[CERT]` number; the fix is a one-line regex change (match both quote styles, or flag the scope), and the cost of NOT having it is a 2.5x-wrong headline census that stood uncorrected for one full block before a later block happened to re-measure it.
- **#2** — bytecode-offset adjacency is a tempting shortcut that reads as rigorous (it cites real `javap` output) while being unverified; this correction inverted a licensing-gate polarity claim that could mislead a downstream architectural decision. The fix (read the branch instruction) costs nothing extra since `javap -c` output is already being read.
- **#3** — a `[INFER — corpus-absence]` hedge is honest but still leads a reader toward "probably new in N5" when the real explanation is a search-term mismatch; retrying with 2-3 morphological variants is cheap and would have caught this in the same session rather than needing a second block to correct it.
- **#4** — this is a second, independent bug in the exact mechanism the pending delta #7 (retro 2) proposes absorbing; landing #7 without also fixing the whitespace-anchoring issue would re-introduce a known silent-failure mode (`decompile_failure_markers: 1` but `fallback_used: false`) into the kit's shared tool the moment it is absorbed.
- **#5** — without a named merge rule, every future tool invocation that hits the same license wall risks spawning its own blocked-gap row, inflating the open-gap count with duplicates that all resolve the instant one root cause (a license) is fixed; this wave already did the right thing twice (B17→B29) by convention, so naming the rule costs nothing and prevents backslide.
