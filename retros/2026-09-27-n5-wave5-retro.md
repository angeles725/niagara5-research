For each delta above, one line of rationale (WHY it matters, what it costs, expected impact):

- **#1** — this wave's own evidence shows a solo count is not self-trustworthy regardless of HOW the miscount happens (regex bug in wave 3, plain transcription error here); naming "provisional until a second count agrees" as the standing rule, rather than patching each mechanism-specific bug as its own delta, would have caught both without needing two separate fixes.
- **#2** — without a named inbound-truncation protocol, a future delegated agent facing a corrupted brief might either stall indefinitely waiting for a reply, or silently narrow its own scope without flagging the gap — this wave's actual behavior (ask once, proceed from visible labels, name what was missed) is exactly right and costs nothing extra to codify as the default.
- **#3** — a live crypto-downgrade acceptance path is a materially different class of finding than a routine API-shape observation; burying it in ordinary block prose risks it being missed at exactly the moment (retro/session-close) when it should reach a human decision-maker fastest.
