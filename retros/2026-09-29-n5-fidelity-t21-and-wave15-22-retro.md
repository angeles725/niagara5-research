For each delta above, one line of rationale (WHY it matters, what it costs, expected impact):

- **#1** — The kit already requires a negative control, but in generic terms. This run shows two different failure modes of one oracle class that need two different controls. A whole session's headline numbers were retracted because only one kind existed. The cost is one mutation file per normalizer, and it prevents publishing false "exact" rates.
- **#2** — "Empty equals empty" produced three false positives in three unrelated places (registry, signature script, JS oracle). Only a code review or a manual look caught each one. A literal-digest check is a few lines in `verify-sources.sh`, has zero false positives, and catches the registry case mechanically.
- **#3** — Without the triage rule, 74 harness-caused failures would have been reported as decompiler defects. Reading the launcher is cheap, and it makes the "tool vs harness" split auditable.
- **#4** — The prose rule has now failed across two consecutive runs of the same target. A hook costs one small script. It turns a silent session kill into a refused command with the fix in the message.
- **#5** — Private-by-construction at creation does not hold if visibility later changes. The target's own `.gitignore` contradicts the live visibility, and nothing in the kit notices. A read-only check is cheap and keeps the owner's choice while making the exposure visible.
- **#6** — This is low-cost, and the pending install-roots proposal already implies the same mechanism. Folding the runner and load path in avoids a second per-target list.

## Honest verdict

This run surfaced two genuinely new, high-value kit gaps, both about oracles that say "equal" when they should not:
- An equivalence oracle needs both a wrong-pair control and a per-rule near-miss mutation suite (#1). One kind cannot stand in for the other, and missing the second kind cost a full retraction.
- "Empty equals empty" hit three unrelated places in one run (#2). The registry case can be gated mechanically today.

#3 is a smaller, new triage rule. #4 and #5 turn existing prose into mechanical checks: one for a rule that keeps recurring (pkill), one for an invariant that drifted after creation (remote visibility). #6 is a low-priority extension of a pending proposal. The RDD review-budget and absence-claim lessons were already proposed by earlier retros of this target and are not re-proposed.
