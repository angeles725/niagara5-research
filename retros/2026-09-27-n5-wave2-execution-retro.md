For each delta above, one line of rationale (WHY it matters, what it costs, expected impact):

- **#1** — a build that silently writes into a shared, read-only vendor install is a corruption risk with no error signal; a cheap before/after directory snapshot turns an invisible footgun into an immediate diff, at the cost of one extra `find`/`ls` per §19 build invocation.
- **#2** — without a named recovery path, an agent hitting `native_stop_required` after an incomplete correction might try to force-resume a dead lineage instead of starting the cheap, correct fresh RED→GREEN commit; this run's SEC-11 sequence is a clean worked example to codify from.
- **#3** — the existing kit rule covers CITING a sibling's evidence but is silent on CORRECTING a sibling's error; without a named path, a future agent either skips the fix (leaving a known-wrong fact live in another corpus) or invents an ad-hoc mechanism each time.
- **#4** — turns a reactive per-port gitignore addition into the default authoring order, preventing even a momentary window where a client-owned file could be staged or committed by an unrelated `git add -A`.
- **#5** — low-cost codification of a pattern that already worked cleanly this run (zero collisions across 12 parallel-ish block writes); naming it saves the next heavy campaign from re-deriving the same split.
- **#6** — a state file that silently loses a column is worse than one that errors, because downstream tooling (`research-sdd-status.sh`) may misparse every later row, not just the corrupted one; same severity class as the first retro's #1 but a distinct bug shape, so it needs its own rule rather than folding into that one.
- **#7** — the kit's own decompile tool would hang exactly the way Vineflower hung on `bajaui.jar` in this bake-off, for ANY future target that decompiles Java-17+ bytecode with UI/records-heavy classes; the target-local `tools/n5-decompile.sh` already proves the fix pattern works, so absorbing it removes a known reproducible hang from the shared tool.
